## 存储与命名方案

采用“IP目录 + 少量功能目录 + 稳定编号及内容名称”，同时在 JSON 中保留多个标签。下面是未来入库的目录约定，尚无对应图片：

```text
stickers/vintage-cat/
  greeting/       打招呼、早安、晚安、道别
  affection/      抱抱、贴贴、亲亲、感谢
  celebration/    开心、夸赞、加油、庆祝
  reaction/       惊讶、疑惑、围观、无语
  complaint/      吐槽、疲惫、崩溃、拒绝
  comfort/        委屈、哭泣、陪伴、安慰
```

文件名例：`vc-001-wave-hello.gif`。这是命名示例，不对应已下载图片。

每张图只存一份，按最常用的聊天功能选文件夹。相同图片跨功能使用由索引标签处理，不重复复制。同一动作的静态与动态版本若都保留，应使用不同编号。图片文字、名称和画面分别记录；不为无标题的图片编造“官方名称”。

JSON 追加字段建议：

- `id`：vc-001 等稳定且唯一的编号。
- `name`：方便理解的中文描述名，例如“挥手打招呼”。
- `original_name`：来源明确提供的名称；无名称用 null。
- `name_origin`：official / source_title / descriptive，分别代表明确确认的官方名称、来源标题、自己根据画面起的描述名。
- `category`：主功能目录名。
- `emotion_tags`：可多选，如开心、亲切、期待。
- `chat_scenarios`：例如“用户分享小进展时回应”。
- `avoid_scenarios`：例如“严肃求助时不使用夸张吐槽图”。
- `image_text`：图片原有文字，没有则为空字符串。
- `alt`：真实画面描述。
- `path`、`url`、`cdn_url`：仅在实际上传并验证后填入。
- `source_url`：具体图片来源页面，而不是仅填写站点首页。
- `license`、`permission_url`：实际许可名称和依据；不将第三方 IP 标为 MIT。

## 优先挑选的功能

优先覆盖日常问候、温柔陪伴、分享快乐、夸赞、疑惑、惊讶、无语、疲惫、轻松吐槽及道别。先挑少量清晰、用途明确、能覆盖这些场景的图片；避免用大量近似图片增加选择负担。所有分类都要在实际查看图片后完成。
